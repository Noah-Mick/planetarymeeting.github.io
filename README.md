# planetarymeeting.com

Art portfolio for Livia Burkhardt — a plain static site rebuilt from the
original WordPress version.

## Pages

| File | Was |
|---|---|
| `index.html` | Illustration (the WordPress home page) |
| `sketchbook.html` | `/sketchbook/` |
| `fine-art.html` | `/fine-art/` |
| `about.html` | `/about/` |
| `store.html` | `/under-construction/` |
| `contact.html` | `/commissions/` |
| `404.html` | new — shown for any bad URL |

Each page holds its own copy of the header and footer. That is deliberate:
it keeps the site dependency-free and instantly editable. If you change the
navigation or the social links, change them in all seven files.

The drawer menu is the exception — it builds itself from the header nav and
footer socials at runtime, so it picks up those edits automatically.

## Running it locally

```bash
npm run serve
```

Then open <http://localhost:8080>. This matches how GitHub Pages serves the
site (including `/about` working as well as `/about.html`). Opening the HTML
files directly from Finder/Explorer also works.

## Adding artwork

**Artwork is published by dropping it in Dropbox** — the artist never touches
this repo. See [docs/adding-artwork.md](docs/adding-artwork.md) for the guide
she uses, and [docs/publishing-pipeline.md](docs/publishing-pipeline.md) for
how it works and how to set up the credentials.

The short version: a scheduled GitHub Action mirrors
`Dropbox/Apps/Planetary Meeting/<Gallery>/` every 15 minutes, builds WebP
derivatives, regenerates the manifest and commits, which redeploys Pages.
Folder name gives the gallery, filename gives the title, and an optional
`01 - ` prefix gives the order.

If Dropbox is unavailable, drop a file in `images/inbox/<Gallery>/` and commit
it — see [images/inbox/README.md](images/inbox/README.md).

### Working on it locally

```bash
npm run build      # rebuild derivatives and js/artwork.js
npm run sync       # pull from Dropbox (needs credentials)
npm run auth       # one-time: obtain those credentials
```

`npm run build -- --force` rebuilds every derivative from scratch.

### Two generated files — don't hand-edit

- **`js/artwork.js`** — every piece, in display order. Regenerated by
  `npm run build`; edits are overwritten.
- **`data/gallery-state.json`** — the source of truth for what's published,
  and the memory between runs that makes renames free and deletions
  detectable. Maintained by `npm run sync`.

To change what's on the site, change Dropbox — not these files.

### Untitled sketchbook pages

Titles that look like a camera filename (`Photo Nov 28 2023, 6 55 59 PM`) are
treated as untitled and get no caption, so a file dropped straight from a phone
needs no renaming. Rename it to something real and the caption appears.

## How images are handled

Two WebP derivatives per piece, both committed:

| | Size | Used by |
|---|---|---|
| `images/<gallery>/thumb/<slug>.webp` | 900px, q80 | gallery grid |
| `images/<gallery>/web/<slug>.webp` | 2000px, q82 | lightbox |

**Full-resolution originals are not committed and not served.** Dropbox holds
the masters. Currently 26 MB of derivatives stand in for 94 MB of originals,
and the lightbox went from up to 7.8 MB per image to about 330 KB.

Thumbnail dimensions are recorded in the manifest so each tile reserves its
space before the lazy-loaded image arrives and the masonry columns never reflow
mid-scroll.

Every image URL is built by one `imageUrl()` helper in `js/gallery.js`. If the
images ever move to a CDN or object store, that function is the only thing that
changes.

The 57 originals from the WordPress import still sit in `images/<gallery>/`.
They're ignored by the build and kept only because they're already in git
history — nothing reads them.

### A trap worth knowing about

Windows is case-insensitive; GitHub Pages is not. Writing `Aquarius.webp` on
Windows when `aquarius.webp` exists silently reuses the old lowercase name, so
the repo ends up holding a file the manifest can't address — renders perfectly
on your machine, 404s on the live site. `build-gallery.js` removes case
variants before writing to prevent exactly this. Don't remove that step.

## The contact form

**The form is not connected yet.** It's fully built, but a static site can't
receive form submissions on its own, so it needs a third-party endpoint. Right
now the page says so plainly and the Send button is disabled — better than
silently dropping messages.

To switch it on with [Formspree](https://formspree.io) (free tier handles file
attachments):

1. Sign up and create a form.
2. Copy the form ID it gives you (looks like `xyzabcde`).
3. In `js/contact.js`, set:

   ```js
   var ENDPOINT = 'https://formspree.io/f/xyzabcde';
   ```

Any service taking a multipart POST works the same way — Formspark,
Web3Forms, Netlify Forms, or your own handler.

## Deploying to GitHub Pages

The repo is already named `planetarymeeting.github.io`, so pushing to `main`
publishes it:

1. Push the branch.
2. Repo → Settings → Pages → Source: **Deploy from a branch**, branch `main`,
   folder `/ (root)`.

It'll be live at `https://<username>.github.io` within a minute or two.

### Pointing planetarymeeting.com at it

Only do this once you're happy with the site and ready to drop WordPress —
it moves the live domain.

1. Add a file named `CNAME` at the repo root containing exactly:

   ```
   planetarymeeting.com
   ```

2. At your domain registrar, replace the WordPress DNS records with:

   - Four `A` records for `@` → `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153`
   - One `CNAME` record for `www` → `<username>.github.io`

3. Repo → Settings → Pages → Custom domain → enter `planetarymeeting.com`,
   then tick **Enforce HTTPS** once the certificate is issued.

DNS can take a few hours to propagate. Keep WordPress alive until the new site
resolves.

## Design notes

Type and colour are carried over from the WordPress theme so the site reads
the same as before:

- Font: Spline Sans Mono (Google Fonts)
- `#4b2639` body copy · `#b26d78` navigation · `#a0917a` links

Added along the way: keyboard navigation and visible focus rings, a skip link,
arrow-key and swipe support in the lightbox, alt text, per-page titles and
meta descriptions, and a 404 page.

### Navigation extras

A **back-to-top button** sits bottom-right on every page. It fades in once
you've scrolled about three-quarters of a screen, and hides itself while the
lightbox or drawer is open. It respects `prefers-reduced-motion` — no smooth
scroll for anyone who's asked the OS not to animate.

A **drawer menu** slides in from the right, opened by the hamburger button
pinned to the top-right corner. It's present at every screen width. The inline
navigation under the logo is untouched — the drawer is a second route to the
same pages, for when you've scrolled past the header.

It closes on Escape, on clicking the overlay, on following a link, or on
pressing the hamburger again. While open it traps Tab inside itself and returns
focus to the hamburger on close.

The drawer's links are cloned from the header nav and footer socials when the
page loads, so it stays in step with them on its own.

## Local-only files

`images/_unpublished/` holds 51 sketchbook originals from an earlier attempt at
this project that were never published on the live site. They're kept so
nothing was thrown away, but **git ignores them, so they are not backed up.**
Keep your own copies. To publish one, move it into `images/sketchbook/` and add
a row to `js/artwork.js`.
